# Live RAW-derived LogC3 lab — 0.9

This milestone adds a **separate experimental live camera path**, not another name for the SDR/HLG recorder. It implements Camera2 RAW acquisition → GPU reference demosaic/colour development → LogC3/AWG3 → a separately qualified ten-bit encoder, with an independent viewing branch. Code implementation and passing synthetic tests are not physical S23 qualification. No 60-second physical take, all-resolution support, ARRI sensor-range equivalence, firmware unlocking or synchronized RAW audio is claimed.

## User workflow

1. On Android 13/API 33 or newer, open Controls → Settings & exports → **Experimental live RAW-derived LogC3**. The existing recorder stops when its screen is left; its settings and recording paths are not replaced.
2. Run **Test Log recording backend** without a camera/profile. It tests GPU arithmetic and available P010 Image / RGB10 Surface encoder routes and writes a shareable report. An inaccessible decoder is distinguished from an absent encoder interface in the report. `unavailable` is not a pass or proof that other hardware interfaces are impossible.
3. Choose/import an exact device/firmware/RAW-layout-bound profile. Create a manufacturer-derived provisional profile through the 0.8 saved-RAW developer when appropriate. Real colour-chart calibration remains separate. Synthetic profiles are rejected for live camera use. Explicit consent is required for provisional profiles.
4. Select an explicit source crop and output at 24/30 fps. Source is limited to 16 MP in this backend; output is at most 1920×1080. A 1080p centre-crop choice states whether it uses 3840×2160 reduced by two or 1920×1080 without reduction. Full profile crops reduced by 1/2/4 are also offered where supported and at least 600 columns wide. Nothing is upscaled. This is an engineering limit, not a claim about the phone's maximum capability.
5. Enter fixed manual focus in diopters (0 = infinity). Profile ISO/shutter and software white balance remain fixed, and actual sensor exposure/focus results are checked. The live path does not claim that hardware AWB is locked or calibrated; white balancing of RAW is performed by the selected profile.
6. Prepare the preview. GPU/codec tests run again for the selected output. Only after successful preparation and matching RAW frames does Record become available. The monitor offers a practical SDR view or Log signal view; neither changes encoded pixels. The SDR view is not an ARRI display LUT or display calibration.
7. Record/Stop produces video only. Camera recording stops on screen exit, severe thermal pressure, storage reserve, missing metadata, frame-queue exhaustion or an encoder failure. Rotation is requested locked during active work. A bounded 18,000-frame timestamp index ends extremely long takes explicitly (10 minutes at 30 fps, 12.5 at 24 fps); physical thermal endurance is unknown.
8. Share the checked movie together with its `.logc3.json` report. Assign **ARRI Wide Gamut 3 / LogC3, video data levels** in an editor. Orientation is reported but not rotated into pixels. Review the recorded orientation before use. Generic player thumbnails are not colour-correct. Private files must be exported before uninstalling.

## Implementation and ownership

`LiveLogSession` is application-owned and keeps camera callbacks, GPU processing/encoder submission, codec output draining and display rendering on independent owners. It requires an already imported/created matching profile. No camera opens merely because the screen opens. The backend test does not request camera or microphone permission.

Three preallocated RAW copy buffers are joined to exact sensor timestamps. Camera Images are promptly closed after copying real row/pixel strides. Preview overload may drop preview input frames; recording overload stops with a reason. The raw camera queue is bounded; it never grows to absorb unlimited encoder delays. A few queued frames may be discarded at Stop and are counted separately. RAW source pixels are not retained during normal live recording.

`RawLogGpu` uploads integer R16UI samples, uses the shared LogC3/colour contract and bilinear reference demosaic in GLSL, and averages reductions in scene-linear colour. The working Log texture is RGBA16F, with signed values preserved until the explicit output-range decision. A GPU query detects out-of-range components. Without consent, they stop processing; with consent they clamp at the final output stage and affected frames are counted. Exact clipped-pixel and sensor-saturation counts are not measured by this live backend.

P010 output is explicitly generated by a second shader into integer packed bytes; high-bit packing and BT.709 YUV **matrix coefficients** are not a conversion to Rec.709 RGB primaries. This path includes GPU readback and a stride-aware copy to encoder input. It is **not zero-copy**. RAW upload, processing, P010 readback and encoder submission times are measured separately. GPU implementation does not establish real-time performance, especially for full sensor frames.

`LiveLogMonitor` has three separate, reduced-resolution RGB8 preview textures and its own context/thread. A slow display skips preview updates rather than retaining RAW/recording buffers. Preview failures are reported. If native display cleanup times out, its shared resources are retained rather than destroyed beneath an active display worker; that is explicitly unconfirmed cleanup, not a claimed successful teardown.

`LiveLogEncoder` uses asynchronous codec callbacks on a dedicated drain owner. P010 input or a candidate RGB10 linear-storage EGL surface is accepted only after actual encode/decode qualification. The surface route requests no HLG/PQ transfer and no HDR metadata-generation feature. Some devices will reject this route or produce insufficient precision; it then remains unavailable. Successful Main10 output alone is insufficient. Existing HLG capabilities do not automatically qualify this route.

## Precision qualification

Each tested encoder/decoder route must preserve a 1024×128 moving grayscale ramp and colour patches, then reject the same deliberately eight-bit-degraded ramp. Qualification requires averaged grayscale mean error ≤0.75 code, peak ≤2 codes and ≥600 distinguishable levels; colour-patch centres must be within 12 Y/Cb/Cr codes. The selected output dimensions are also exercised. P010 decoding with known crop/plane strides is required by the current verifier; additional decoder interfaces are future coverage work.

The surface route uses an exact RGB10 EGL configuration with explicitly linear storage to avoid an sRGB framebuffer operation. Stored Log samples must survive the codec's RGB-to-YUV stage, as demonstrated by the same ramp and colour controls. It is never enabled just because EGL creation succeeds. A driver that transforms/clips/quantizes these samples fails qualification; rewriting metadata cannot repair that loss.

GPU arithmetic tests compare all four Bayer arrangements, reflective crop boundaries and reductions 1/2/4 against the CPU reference. Log RGB error must be ≤0.001 and packed P010 error ≤2 codes. Synthetic GPU/codec measurements are not sensor bit-depth or dynamic-range measurements.

## Timing, files and truth boundaries

Recorded PTS = `(sensorTimestampNs - firstRecordedSensorTimestampNs) / 1000`. The recorder does not replace real intervals with frame numbers, synthesize missing frames or silently slow motion to nominal cadence. Full decode validates the supplied timestamp list; cadence is assessed separately. Microsecond truncation is stated. Audio synchronization is not implemented.

On Stop the encoder drains EOS with bounded waits and finalizes MP4. A full P010 decode validates bit depth, HEVC signalling, dimensions, frame count and original relative timestamps before the file is promoted from `.partial.mp4`. This live verification **does not compare each picture to the original RAW**, since normal live recording does not save that original. The report explicitly marks `pixelSourceComparison=false`. Controlled retained-RAW experiments, CPU/GPU comparisons and backend fixtures remain the source-comparison evidence.

HEVC VUI is reauthored to unspecified primaries/transfer (2/2), BT.709 representation matrix (1), limited range. Only SPS signal metadata changes, not picture NAL payloads. Failed, interrupted and unverified outputs remain in Retained live exports as `.partial.mp4`; they may or may not be playable. No source video or previous export is deleted to conceal an error. Once a checked movie exists, report/library failures never delete it.

Reports include app/device identity, exact profile, explicit source crop, backend/GPU proofs, frame accounting, relative sensor timestamps, max stage times, cadence, clipping permission and preview state. A structurally checked file is not a physically qualified recording mode. No firmware operation occurs.

## Tests and next physical gate

The existing build/lint/JVM/emulator/host campaign remains enabled. New JVM tests cover relative timestamp mapping, bounded frame indices, crop/budget policy and P010 layout. Instrumentation runs the actual GPU comparison, actual codec-route qualification where exposed, and screen recreation without implicit capture. `scripts/check_live_log.py` refuses mixed revisions and any conversion of `unavailable` into a codec pass.

Next physical gate: run the standalone backend report on the exact phone, then a matching-profile live take. Inspect 60 seconds initially, repeated start/stop, original cadence, preview isolation, heat, optical focus and editor interpretation. Expand to longer recordings, faster capture and larger sensor/output modes only from those results. Add RAW audio synchronization after a video-only mode is demonstrated. Hidden higher-resolution/HDR access and targeted HAL/firmware investigation remain independent work.
